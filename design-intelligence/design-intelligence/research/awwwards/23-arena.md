## 13. Design Principles Extracted
1. **Restraint can be a genuine values statement, not just an aesthetic preference** — when a product's
   actual point of difference is "we don't optimize for your attention the way other platforms do,"
   visual restraint directly embodies that claim rather than merely looking clean. Use when a product's
   core value proposition is explicitly anti-engagement-optimization. Failure mode: claiming this
   positioning while still using conventional engagement-maximizing patterns (infinite scroll, algorithmic
   feed) undermines the restraint claim's credibility.
2. **An associative, non-hierarchical organizing model (loosely connected collections) can better serve
   genuinely exploratory, non-linear thinking than a folder hierarchy** — appropriate for research/
   ideation tools. Avoid for tools where users need to reliably retrieve a specific known item quickly —
   there, more conventional, predictable hierarchy usually serves better.

## 14. Anti-Patterns
Do not adopt minimal visual chrome as a purely cosmetic choice disconnected from an actual underlying
product value (as this system's own `principles/` library repeatedly emphasizes) — the restraint here is
argued to work specifically because it's tied to a genuine anti-engagement-optimization product stance.

## 19. Lessons for AI-Generated UI
When a product brief includes any version of "we want this to feel calm/restrained/not addictive," an
AI agent should treat that as a request to actually change underlying interaction patterns (no infinite
scroll, no algorithmic engagement feed, no notification-badge pressure), following this platform's
apparent approach, rather than only applying a visually minimal skin over otherwise conventional
engagement-optimized mechanics.
