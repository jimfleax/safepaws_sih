# 3D Pattern
**What it is**: Real-time or pre-rendered three-dimensional content used as primary interface/content,
not decorative accent.
**When to use**: A genuine spatial concept or product (Bruno Simon's driving-world portfolio; Iventions'
spotlit installations; a real product that is itself 3D, like furniture/hardware configurators).
**When NOT to use**: As a decorative "premium" signal disconnected from any spatial concept the product
actually has — the single most common misapplication of this pattern.
**Layout anatomy**: Scene composition (camera, lighting, object placement) replaces conventional 2D
layout; UI chrome (nav, text) is typically composited on top of or alongside the 3D canvas, kept
achromatic/minimal to avoid competing (`principles/06-color.md`).
**UX rationale**: 3D content must still teach its own controls within the first few seconds
(`immersive.md`) and must degrade gracefully — see performance considerations below.
**Visual variants**: Product configurator (input-responsive, real-time); staged/spotlit showcase
(camera-directed, lower interactivity); fully explorable world (highest commitment, highest risk).
**Responsive strategy**: Provide a genuinely different mobile experience (simplified scene, static
fallback imagery, or a 2D equivalent) rather than assuming WebGL performance parity on phone-class GPUs.
**Accessibility requirements**: A non-3D alternative path to the same core information/content; respect
`prefers-reduced-motion` for any camera/object animation.
**Performance considerations**: The single highest performance-risk pattern in this system — asset
size (models, textures), draw calls, and shader complexity all need explicit budgets and a tested
fallback for low-power devices (`research/awwwards/22-active-theory.md`, `research/awwwards/21-
iventions.md`).
**Anti-patterns**: A spinning 3D product/logo with no functional tie-in to the product's actual value;
3D added because the technology is available, not because a concept calls for it.
**Implementation notes**: Budget performance and design the fallback *before* building the 3D scene, not
after.
